# Cinematic Drama 视觉与声音参考资产指南

## 资产建立顺序

先通读本次情节和全部片段表，再依次建立 style 锁、人物形象卡、角色音色、场景参考，以及武魂、召唤物、生物、关键道具等连续性资产。每类资产都先生成候选、交给用户确认并登记版本；未确认资产不得进入正式视频节点。

为每个资产记录：稳定名称、职责、版本、完整生成 Prompt、生成方式、输入参考、平台与模型、任务／节点 ID、本地路径、出现片段和确认状态。不要用“最新版”代替稳定版本号。

## 参考来源优先级与冲突核对

- 用户明确提供或确认的参考媒体，是该人物、场景、武魂、道具或声音身份的最高优先级来源。实际参考图中的主体类别、外貌、服装、材质和画风，不能被早期脚本概括、文件名或旧 Prompt 擅自覆盖。
- 接收参考媒体后必须实际打开检查，并把可见事实写入资产表；不能只依据文件名或用户一句简称猜测内容。生成前再次对照剧本、资产表、当前素材清单和 Prompt，确保同一元素没有相互矛盾的定义。
- 参考媒体与旧文字冲突时，以已确认参考媒体重写视觉或声音描述并保留旧版本用于溯源。若冲突会改变剧情机制、动作因果或角色身份，停止生成并让用户裁决；不得一边连接参考图，一边要求模型生成另一种主体。
- 用户未确认的候选图不自动推翻已确认设定。候选晋升、换装、改名或替换音色后，先更新当前素材清单，再允许它进入视频节点。

## 人名与口播词汇

- 固定角色的人名优先使用两到三个常用汉字，越简单、越容易一次读对越好。不要为了网文感、古风感或“高级感”使用生僻字、冷僻异体字、复杂叠字或不常见读音。
- 人名必须同时服务人物识别和视频模型发音。已经在实际生成中反复念错的名字，应直接改成更简单的常用名，并同步更新角色表、素材名、音色映射、片段矩阵和后续 Prompt；不要用注音、谐音字串或提示模型“读作某音”长期补救。
- 准确口播不依赖连续拉丁字母等级。等级符号不是剧情核心时，先根据世界观建立一套简短、易读且有类型氛围的中文阶位体系，例如“凡阶、天阶、神阶”；不要用“高级、顶级、最低级”等产品套餐式泛称敷衍世界观，也不让旁白或角色朗读 `SSS`、`S`、`F` 等容易漂移的字母组合。同一部作品一旦确认映射，必须在剧本、资产名、画内信息和所有 Prompt 中统一。
- 资产历史版本可以保留原名与原等级用于溯源，但当前权威角色名、媒体文件名和正式 Prompt 只使用已经确认的简化版本。

## 默认图像模型

- Cinematic Drama 的人物抽卡、场景、武魂、召唤物、生物和关键道具等新资产图，默认优先使用 GPT Image 2。正式生成前仍须通过当前 CLI 查询实时模型名与 schema；平台别名只由对应工具文档解析，不把一个平台的模型名映射复制到其他平台。
- 已确认人物转三视图、同一人物换装、同一武魂形态派生等身份连续性任务必须使用真实图像参考走图生图。用户已经指定 C-Dream 5.0 Pro 或其他派生模型时按该流程执行；“默认 GPT Image 2”不构成把派生任务退回无参考文生图的理由。
- 用户针对具体资产明确指定其他图像模型时遵循该选择并记录版本；不得因画布旧节点、历史习惯或模型推荐静默偏离。

## 反复出现即资产化

先制作完整的“片段 × 可辨识元素”矩阵。任何会在两个及以上片段反复出现，或即使只出现一次但其造型、空间关系、剧情身份必须精确稳定的元素，都必须在正式视频前建立独立参考素材；不得只靠文字让模型在每个片段重新设计。

- 人物：主角、配角、反派和其他需要稳定辨认的角色都建立人物卡。是否有独立台词、戏份多少或是否位于背景，不改变其连续性身份；只有没有固定身份、不会被再次辨认的群演可以不建立人物卡。
- 场景：觉醒台、宗门大殿、固定街道、房间等跨片段场景建立场景图，锁定空间、建筑、固定陈设、材质、主辅色和基础光位。
- 非人物主体：武魂、召唤兽、坐骑、怪物、机甲、载具等只要反复出现或承担关键动作，就建立独立主体参考图。
- 关键道具：武器、信物、特殊装置、核心商品等只要需要跨镜头或跨片段保持造型，就建立独立道具参考图。
- 声音：每个有台词的固定角色建立独立音色锚点；环境声和一次性群众声不为凑数建立音色。

编写每个片段 Prompt 前，从矩阵中筛出该片段实际可见或发声的全部连续性资产，并全部连接到当前视频节点。不得只连接主角而遗漏同场配角、武魂或场景，也不得把本片段没有出现的全片资产一次性塞入。素材数量超过目标模型实时上限时，优先拆分片段、减少同镜头固定主体，或先制作用户确认的组合参考图；不得静默删掉最重要的人物身份参考。

## style 锁

style 锁只描述全片持续不变的视觉语言：媒介、写实程度、人物比例、材质、线条、渲染体系、色彩范围、光影质感和摄影基调。它必须来自用户选定的当前 Mode style 或用户确认的自定义 style。

- 在人物卡、换装卡、场景图和每个视频片段 Prompt 中重复所需的 style 锁，不依赖模型记住上一个任务。
- “半写实 3D 动画”仍然是动画电影渲染：保留经过设计的面部比例、材质概括和国漫 3D 造型，不能漂移成真人摄影、影视剧演员定妆照或照片级皮肤。人物、场景、武魂和视频 Prompt 必须重复同一套文字 style 锁。
- style 锁不固定具体地点、天气、服装、动作或镜头；这些由当前资产或片段单独定义。
- 自定义风格含糊时，先把它整理成可执行的视觉约束并让用户确认，不自行用“高级、电影感、震撼”等空词补足。

## 人物形象卡

### 角色层级与最低资产

- **主角**：跨多个片段推动核心情节。必须有已确认人物形象参考和独立音色参考；默认建议制作三视图，但用户为快速验证明确选择单图路线时可以暂缓。
- **配角**：具有固定身份并跨片段重复出现。必须有已确认人物形象参考和独立音色参考；重要配角或服装细节复杂、需要大量侧背面镜头时制作三视图，次要配角可以只使用质量足够的单张人物参考。
- **路人**：没有固定身份、无需跨片段辨认的群众或功能性人物。不要求人物参考、三视图或固定音色，允许外貌与声音在不同片段随机变化；Prompt 只约束其年龄范围、服装体系、群体行为和整体画风。

人物参考与三视图是两层资产。主角和配角不能因为省略三视图而省略人物参考；只有路人可以完全不建立固定身份资产。

人物的社会身份与视觉吸引力分开设计。“出身普通”“暂时弱小”或“被轻视”不等于长相平庸；当用户要求偶像感、少年英雄感或商业短剧主角吸引力时，人物抽卡应明确健康精壮的体型、清晰有辨识度的五官、适龄青年气质和镜头表现力，同时继续遵守剧本中的身份与服装条件。

### 先抽卡，再制作多视图

1. 先为每个固定角色使用 GPT Image 2 生成独立的 **9:16 竖版正面全身人物候选**。画面只出现一个角色，从头顶到脚底完整可见，面向镜头自然直立，不做战斗、施法、奔跑或戏剧姿势；服装结构、鞋履和必要配饰清楚，背景简洁且不承担具体场景叙事。
2. 每个角色的候选单独保存完整 Prompt 与版本，交给用户抽卡确认。没有确认前不批量派生多视图，也不把多个角色合在一张候选图中比较。
3. 候选确认后，再把这张实际图片作为图生图输入，使用用户指定的 C-Dream 5.0 Pro 或当前确认的派生模型生成下述 16:9 多视图人物卡。不得只复制候选 Prompt 后重新文生图；多视图必须继承已确认候选的脸、发型、年龄、体型、服装和画风。
4. 快速样片或次要配角经用户确认可以停留在单张候选层；主角与重要配角按镜头需要继续完成多视图。省略多视图不等于省略已确认人物参考。

### 固定版式

需要制作三视图时，使用一张 **16:9 横版图片**，并满足全部条件：

- 整张图只有纯白背景，不出现环境、地面纹理、装饰框、道具布景、文字、字母、数字、标签、Logo 或水印。
- 左侧是同一角色的大尺寸正脸近照，只呈现正面脸部身份信息，五官、发型、肤质和年龄特征清晰，不使用侧脸、三分之四侧脸或夸张表情。
- 右侧并列同一角色的正面、标准侧面和背面三张等比例全身视图；三张都从头顶完整拍到脚底，无遮挡、不裁切，站姿中性，比例、发型和服装完全一致。
- 正面、侧面和背面必须清楚展示服装剪裁、层次、领口、袖口、腰部结构、背部结构、鞋履、配饰、材质和主辅色；侧面轮廓与背面服饰不能被头发、披风、手臂或道具无意义遮挡。
- 明确说明四个视图是同一个角色的设计展示，不是四个不同角色。人物卡可以直接作为视频人物参考输入；按当前节点的真实连接顺序编号并在 Prompt 中把它绑定为一个固定角色。

人物卡 Prompt 至少包含：角色身份与年龄、稳定面部特征、发型、体型与头身比例、基础服装的逐层结构和材质、鞋履与必要配饰、所选 style 锁、固定版式，以及无文字和纯白背景要求。

### 常规服饰状态

人物卡只记录角色在该服装版本下的常规、干净、完整状态：

- 不加入只属于具体场景的沙尘、雨水、泥污、血迹、汗湿、烧灼、破败、战损、风吹动态、魔法辉光、烟雾或戏剧化环境反光。
- 不用姿态、表情、粒子或环境光效代替服装设计。场景造成的临时状态在对应视频 Prompt 中描述。
- 服装本身设定为旧衣、补丁衣、破损制服或带发光结构时，可以如实呈现其设计固有部分，但必须与“进入某场景后临时变脏或损坏”区分。

### 换装与人物卡版本

- 角色在某段剧情中更换服装时，为该服装建立新的独立人物卡，并在角色资产表中标明适用片段。
- 新人物卡必须使用图生图，把同一角色上一张已确认人物卡作为实际图像参考；不得仅复制文字描述后使用文生图重建。
- 图生图 Prompt 明确锁定面部身份、发型、年龄、体型、头身比例和非更换部位，只替换本次服装与必要配饰，并重新输出完整的 16:9 无文字多视图人物卡。
- 如果换装同时改变发型、年龄、体型或身体状态，逐项列出并先取得用户确认；不把生成漂移解释为剧情变化。
- 换装卡仍展示干净、常规服饰状态。沙尘、雨水和战损等场景效果继续留在视频 Prompt 中。

## 角色音色参考

为每个有台词的角色建立一个独立声音锚点。多人共用同一音色必须是用户明确的创作决定，不是缺少资产时的兜底。

1. 先从[内置音色库](../../references/reference-asset-library.md)和宿主项目明确登记的音色中展示可用候选，或根据角色年龄、性别表达、音域、质地、气息、语速、节奏、口音与表演状态生成新候选。
2. 新候选遵循[音色参考与音频转换指南](../../references/voice-reference-guide.md)的独立候选生成、纯人声约束、音轨分离和 WAV 规范；候选只属于当前作品，除非用户明确确认加入公开音色库。
3. 每个角色的候选必须由用户听审并确认。记录角色与音频的一一映射、标准化文件、来源、版本和状态。
4. “任务成功”只证明生成完成，不证明角色音色已经区分。若多个候选在音域、音质、年龄感、气息和节奏上听起来实质相同，整组视为未通过并重新设计差异后生成；不得仅换文件名把相同听感登记为三个角色。
5. 正式片段只连接当前片段实际说话角色所需的音色参考。Prompt 按实际连接顺序声明 `音频N仅用于参考[角色名]的音色`；准确台词只来自当前 Prompt 的 `{}`。固定角色在本片段没有台词时，不连接该角色音频。
6. 只在单个片段说话的一次性角色可以直接在 Prompt 中定义年龄、音域、音质、气息、语速和表演状态，不必建立跨片段声音锚点；一旦计划再次出现并说话，就升级为固定角色音色资产。
7. 多人对白时分别定义说话人、音色参考和台词，保留自然停顿与可见反应。15 秒内角色切换过多时拆分片段，不用加快语速硬塞。

## 场景参考图

为反复出现、需要跨片段保持空间关系，或对剧情调度重要的场景建立参考图；一次性且结构简单的场景可以只用文字定义。

- 正式横版作品的主要场景参考默认生成一张 **16:9 静态图**，画面本身不表现镜头运动或连续时间过程。它要为后续多个 16:9 片段提供稳定的空间、尺度和美术依据。
- 场景图清楚展示空间结构、出入口、前中后景、固定建筑、主要家具或道具、材质、主辅色、光源方向和可用于调度的路径。
- 默认不放关键人物，避免把某个动作或人物位置固化到所有片段；只有必须锁定人物与场景尺度或复杂站位关系时才加入，并明确它只参考空间关系。
- 场景图必须遵循同一个 style 锁。它负责具体地点与空间设计，不单独充当抽象“画风参考图”。
- 时间、天气、季节、灯光或重大陈设变化会改变镜头可见状态时，建立明确的场景版本，例如“祠堂内景-白昼-v1”和“祠堂内景-烛火夜-v1”；不得让一张图同时代表互相冲突的状态。
- 场景中临时出现的烟尘、人群、战斗破坏或天气过程通常写入视频 Prompt；只有该状态需要跨多个片段稳定持续时才建立新的场景状态参考。

## 武魂、召唤物与关键道具参考

- 每个反复出现或承担关键剧情动作的武魂、召唤物、生物和关键道具建立独立参考图，不把它们当作角色 Prompt 中顺带描述的特效。
- 参考图使用干净、无文字、无遮挡的展示状态，清楚呈现整体轮廓、比例、结构、材质、主辅色、发光部位和稳定识别特征；不加入只属于某个镜头的攻击动作、碰撞、破坏、烟尘或环境污染。
- 武魂具有常态、巨大化、战斗态或受损态等会跨片段持续的明确形态时，分别建立版本并记录适用片段。由同一主体变化而来时，新版本必须以上一张已确认参考图走图生图，锁定核心造型关系。
- 人物与其武魂分别承担人物身份和非人物主体身份。视频节点需要同时出现两者时，两张参考都要连接，并在 Prompt 中分别绑定；不得期待人物卡自动定义其武魂。
- 武魂与角色之间的归属、出现方位、尺度和发光交互由当前片段 Prompt 描述；参考图负责固定造型，不固定每个镜头的动作和站位。

## 参考资产确认检查

进入视频 Prompt 阶段前确认：

- 每个主角和配角至少有一张已确认人物参考；当前计划要求三视图的角色，其人物卡是 16:9、纯白背景、无文字，左侧正脸、右侧正／侧／背全身，四个视图确属同一角色。
- 服装细节在正面、侧面和背面都清楚，且没有混入场景污染与临时战损。
- 每张换装卡都有已确认人物卡作为真实图生图输入，并保持同一人物身份。
- 每个说话角色都有唯一、已确认、可连接的音色版本。
- 不同固定角色的音色听感具有可辨识差异；生成成功但听感近似的候选没有被误登记为定稿。
- 音色年龄感、性格和角色定位一致；成年或青年角色没有因为高音域被生成成儿童或低龄少年声。需要沉稳青年男声时，明确中低音域、克制节奏、温暖但不稚嫩的青年质地。
- 已实际打开检查用户提供的参考媒体，资产表和 Prompt 没有用旧文字覆盖参考中的主体身份或画风。
